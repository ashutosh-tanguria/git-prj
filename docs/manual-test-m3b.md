# M3b manual GitHub checklist

Use disposable repositories and short-lived fine-grained tokens. Enter tokens only in Connect. Revoke them afterward. Automated fixtures and the six sample captures do not verify a real account.

1. In Chrome, Edge and Firefox, record browser version, OS and keyboard layout. Focus the file list and try Alt+N, Alt+M and Alt+P. Confirm that the intended action opens without a browser menu. Repeat from a text field and confirm that typing is left alone. Headless key delivery is only automated evidence, not this native-menu check.
2. Connect with Contents read/write and Metadata read on a selected throwaway repository. Review both token presets. Confirm the recommended preset does not ask for creation permission by default.
3. Open New repository by button and Alt+N. Check Private and Add a README file are initially selected. Enter spaces, an invalid reserved name and an existing name, then a unique valid name. Confirm inline validation and availability feedback.
4. Choose Public. Confirm Create remains disabled until the public checkbox is checked. Return to Private, then Public again and confirm the checkbox resets. Cancel without creating anything public unless you intend to do so.
5. With a token authorized for creation, create a private repository with a README. Confirm the new Location opens and the created notice includes its visibility. Inspect the README and default branch on GitHub. If the owner's default is not main, branch rename also needs Contents write and Administration write. A refused rename must open the created repository on its actual branch and show a warning, without attempting a second creation.
6. Try a token without creation permission. Confirm the permission message, bare github.com/new link, token guide and Refresh repositories action. Create on GitHub yourself, return and refresh. Organization membership in the Owner selector is a candidate, not proof that organization policy allows creation.
7. Browse a folder such as semester-5. Upload three small disposable files. Confirm guard review, durable staging and the correct folder paths in Pending review. Press Push. First use requires full review. Check the generated English subject and edit it if desired.
8. In Change destination, try repository and existing-branch suggestions and folder autocomplete. Enter semester-6/week-2 as a new path, apply it and verify all three pending paths. Push once and confirm exactly one commit places all files there. The commit link must open the actual commit.
9. Select Always push here and apply. Stage another three files while browsing elsewhere. Confirm the pinned repository, branch and folder are used before guard review. After a successful first push, press Push and confirm the compact popover. Its destination and primary action must name the target. Edit the message, push once, and verify one commit with the edited text.
10. Uncheck Always push here and apply to remove the pin. Confirm later uploads use the browsing destination. Changing destination, first use, public visibility, file or repository warnings, blocks, sensitive names and upstream collisions must require full review. No checkbox approval is remembered across changed pending work or new reviews.
11. Stage a file, then change the same path on GitHub. Press Push and confirm Quick push is excluded. Attempt Push in full review and confirm the conflict choices appear without overwriting. Discard the disposable work when finished.
12. Select a file, Cut, browse another folder in the same repository and Paste. Check the preview before staging. Push and verify the old path is removed and the new path reuses the original blob SHA. Repeat with Copy and verify the source remains. Cross-repository Cut is refused until verified transfer support; Copy is available through guarded staging.
13. Try New folder, Rename and Delete with disposable files. New folder discloses and stages a .gitkeep marker. Rename and Delete stage file operations and do not immediately change GitHub. Undo, Redo and Discard should recover each staging operation. Folder-wide clipboard, rename and delete operations are currently refused explicitly.
14. From library home, choose Upload files, select its destination and folder, then choose files. Confirm the correct repository's guards appear before staging. With no repository, create one using New repository first.
15. Open Settings and change New repository from Alt+N to an unused binding such as Alt+K. Save, reconnect after reload and test persistence. Try duplicate bindings and a reserved binding such as Control+P and confirm rejection. Repeat the accepted mapping in all three browsers. Confirm visible buttons still work when a browser intercepts a shortcut.
16. During Push, verify destination editing and pending mutations are unavailable. Cancel before the ref update and verify pending work is retained. Once the final ref update begins, cancellation must be unavailable. Check success and failure paths without retrying blindly after a network failure.
17. Repeat the dialogs at 360px width, 200 percent browser zoom, in light and dark, and using only the keyboard. Check scrolling, focus return, visible focus, Hindi copy and the screen-reader announcements. These remain manual release checks.

Record outcomes without credentials. Delete disposable repositories and revoke the tokens yourself after inspection.
